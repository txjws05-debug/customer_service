规定 P0（6 天）+ P1（14 天）改造的测试范围、策略、前置资产、执行顺序、准入准出与具体用例，作为验收依据与回归基线。

### 1.2 范围

| 阶段 | 改造项 | 覆盖 |
|---|---|---|
| P0 | C-01 鉴权与审计、C-02 对象级授权、C-03 备份恢复、C-04 回滚、C-05 LLM 治理、C-06 暴露面收口 | 全量 |

| 阶段 P2 | 人工接管、知识库管理、限流 | 不覆盖 |

**不测**：真实支付渠道、多租户、模型回答质量评分（只做「不编造具体数字」「不串号」的可机判断言）。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 服务令牌 | `X-Service-Token`，Agent→中台凭证；**持有者可跨用户操作**，故为 Prompt 注入的高危通道 |
| operator 令牌 | `X-Operator-Token`，运营端**静态**令牌 |
| warn 模式 | `AUTH_ENFORCE=warn`：C 端校验失败放行并留痕，运营端仍失败关闭 |
| 测试 SKU | 专供评测的规格 `SKU90001`，**每条用例开始前**重置库存 9999 |
| 幽灵订单 | 客户端收到失败响应但库中已存在订单 |
| golden 表 | 从设计文档手写的期望矩阵（`tests/data/order_matrix.json`），**不从代码导出** |
| 优先级 | 本文档一律指**用例优先级** P0/P1/P2；改造阶段写「阶段 P2」，缺陷级别写「缺陷 P0～P3」 |

## 2 测试策略

### 2.1 分层

| 层级 | 内容 | 工具 | 执行位置 |
|---|---|---|---|
| L1 单元 | 状态机 golden 矩阵、脱敏、幂等 SQL 语义 | pytest（无需 PG） | 本地/服务器 |
| L2 接口 | 鉴权矩阵、授权、幂等、指标、输入边界 | pytest + httpx（真实 PG） | 服务器 |
| L3 集成 | 对话→中台→DB、迁移、备份恢复 | 脚本 + curl | 服务器 |
| L4 端到端 | 多轮评测 ≥20 条、会话与上下文 | `task_eval` | 服务器 |
| L5 非功能 | 并发、延迟、浸泡、故障注入 | 脚本 | 服务器（**维护窗口**） |

**硬约束**：本地无 Docker，L2 以上只能在服务器执行（CSC-FS-001 T-04）。L5 会中断服务，须安排在 **02:00–05:00** 并提前 `df -h` 检查磁盘。

### 2.2 左移与防恒真

- 状态机、脱敏、幂等判定必须 L1 覆盖；
- **L1 断言不得 import 被测常量自身**：`TC-S01/S02` 用 `tests/data/order_matrix.json`（手写自设计表格）驱动，否则实现改了用例跟着改，恒真；
- 与现有 `tests/test_shop_rules.py` 的 5 组业务断言并存：G1 用 `-k "not matrix"` 排除矩阵，避免重复计数。

### 2.3 门禁

| 门禁 | 触发 | 失败处置 |
|---|---|---|
| G1 单元全绿 | 每次提交 | 阻止合入；**`skipped > 0` 视为失败**（防连不上库时"0 执行全绿"） |
| G2 鉴权/授权矩阵全绿 | 发布前 | 阻止发布 |
| G3 smoke 四项 + 反向（任一失败即 exit 1） | 每次部署后 | 自动回滚 |
| G4 多轮评测：首轮 ≥90%，此后 ≥ 归档基线 95% | 每次发布 | 告警；CI 恢复后升级为门禁 |
| G5 备份恢复演练 ≤30min | 每月 | 连续 2 次失败升级为缺陷 P0 |
| G6 镜像与 schema 成对回滚 | 每次发布前 1 次 | 阻止发布 |

| 规则 | 内容 |

## 8 故障注入（11 类，对齐 CSC-HL-002 §8 的 12 类）
