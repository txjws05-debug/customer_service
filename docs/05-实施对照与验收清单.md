## 四、与设计文档的偏差（必须如实记录）

| 设计里写的 | 实际做法 | 原因 |
|---|---|---|
| JWT 校验用 `pyjwt` | 标准库 `hmac` + `hashlib` 实现 HS256，`alg` 只接受 HS256 | 服务器访问不了 PyPI，且镜像重建受限；实现等价且算法被固定，反而更难被 `alg=none` 绕过 |
| 用 GitHub Actions 构建发布 | 服务器本地补丁镜像（`COPY ws /app/ws`）+ `IMAGE_TAG` 切换 | 上不了 GitHub；补丁镜像不跑 `uv sync`，不依赖 PyPI |
| `/metrics` 用 `prometheus_client` | 自实现 counter/gauge/histogram 与文本格式（约 180 行） | 同上，装不了包；自实现可用测试兜住格式正确性 |
| Alembic 随镜像提供 | 迁移跑在一次性容器里，alembic 由离线 wheel 装入；`pyproject` 已加依赖 | 同上；正式 CI 构建时会自带 |
| AUTH_ENFORCE 一次开启 | 先 `off`（零行为变化）→ `warn` → `on`，三级灰度 | 一次性强制会立刻打断所有在线会话 |

## 五、已知限制（写清楚比藏起来好）

1. **备份与数据库同盘**：盘坏则备份一起丢，未做异地/对象存储。
3. **`audit_log` 表未建**：审计目前只有日志，没有入库，无法按操作者检索。
4. **uvicorn access log 仍有健康检查噪声**：每 15 秒一行，未加 `--no-access-log`（保留原始 HTTP 层视角）。
5. **评测账号无清理接口**：每轮评测会留下 `eval_*` 用户与购物车记录，需人工清理。
6. **中台无指标**：只有 Agent 侧有 `/metrics`，中台的可观测性依赖 trace 日志。
7. **限流是进程内实现**：单实例够用，多副本部署时必须换成 Redis（接口已隔离在 `acquire_chat()`）。
8. **人工接管只有 API，没有运营界面**：队列目前要靠 curl 或脚本操作，没有值班台页面；也没有「客服在页面上回复用户」的通道（用户侧只收到固定话术）。
9. **知识库删除是临时的**：重建索引从语料文件重灌，被删的条目会回来；永久删除要改语料文件。
10. **知识库管理页是后端吐的 HTML**，不是 Next.js 页面（前端镜像重建需要 npm，服务器连不上）；没有上传/解析文档的能力。
11. **补丁镜像不是「从源码完整构建」**：底座仍是旧镜像，正式构建应在网络可用时用根 `Dockerfile` 重做一次并与当前行为对比。
